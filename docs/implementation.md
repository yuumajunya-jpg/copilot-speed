# Copilot Speed の実装

## 0.4.0 の変更

ポップアップに、利用者が押したときだけ動作する診断と結果保存を追加した。
遅延の計測、購読カウンター、操作の記録、設定 UI は追加していない。
通常の状態応答はこれまでどおり状態と理由だけを返し、診断要求にだけ照合の詳細を返す。

MAIN world は対象モジュールを照合した時点のスクリプトのホスト名とファイル名、両モジュールの有無と SHA-256 を保持する。
診断時には、既存のページ内スクリプトを通じてその詳細を取得する。
応答待ちのタイマーは診断要求中だけ動作し、通常利用中のタイマーや監視は追加しない。

バックグラウンドは診断するタブの実際の URL と設定・権限を確認し、許可された対象ページの最上位フレームだけで読み込み状態を取得する。
取得するのは `document.scripts` のファイル名とホスト名、既知の形式のグローバル名、iframe の数とオリジンである。
ページ上のスクリプトを取得・実行したり、会話 DOM や入力欄を読み取ったりしない。
グローバルを調べる際にも getter は実行しない。
iframe 内のコードは調べず、iframe の有無とホストを切り分けの補助情報にする。

ページから来る照合結果は型と長さを検証し、許可したフィールドだけを採用する。
ページのパス、スクリプト URL のディレクトリ、クエリ、フラグメント、任意の追加フィールドは診断結果に残さない。
結果はポップアップ内にだけ保持し、明示的な保存操作でローカルの JSON ファイルを作る。
サイトへの外部送信、クリップボード操作、追加のホスト権限要求は行わない。

最適化の適用条件自体は変更していない。
診断の追加によって未対応のコードを差し替えることはない。

単体テスト 38 件と、隔離した Chromium のブラウザ結合テスト 17 項目が通過した。
診断コード、照合結果、JSON の保存、ページやスクリプトのクエリ文字列と入力内容を含めないことを確認した。

## 0.3.0 の変更

対象 URL の唯一の設定元を `manifest.json` の `host_permissions` にした。
設定 UI や保存されたパターン一覧を使わず、ファイル編集後に拡張機能を再読み込みして反映する。
`lib/targets.js` に正規化、照合、旧設定の移行処理をまとめた。
バックグラウンドと状態取得用スクリプトが `chrome.runtime.getManifest()` から同じパターンを読み、ポップアップの判定にも使う。

有効設定だけを `enabledPatterns` に保存する。
初回更新時に `enabledOrigins` の有効設定を既存パターンに移行する。
パターンが重複しても、分離環境の状態取得用と MAIN world の最適化用の 2 登録にまとめるため、最適化を二重注入しない。
設定ファイルから削除されたパターンの登録と有効設定は、拡張機能の再読み込み時に除去する。
保存に失敗した場合は前の登録に戻す。
スクリプトと通信できないタブでも、対象に一致して権限があればスイッチを操作でき、再読み込みを案内する。

任意サイトへの包括的な必須権限や、任意ホスト用の追加権限要求 UI は使わない。
`activeTab` はポップアップを開いたタブの URL を取得するために使う。
ホスト権限はパスで制限できないため、ホスト範囲の許可と、スクリプトを注入するパスの設定を区別する。
パターンと権限の仕様は Chrome の [Match patterns](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns) を参照。

最適化のファクトリー照合とトップフレームだけに注入する方針は変更しない。
新しい URL の指定は、そのページの内部実装への対応を保証しない。

0.3.0 の確認では、単体テスト 30 件とブラウザ結合テスト 13 項目が通過した。
結合テストでは拡張機能のコピーの `manifest.json` だけを変更し、別ホストのパス指定で判定と注入が一致すること、指定パス外を変更しないこと、ページ内スクリプトの読み込み前でもスイッチを操作できることを確認した。

## 0.2.0 の変更

運用時に必要な高速化、サイト単位の設定、適用状態、異常時の停止だけを残した。
送信遅延の計測、入力操作の監視、会話 DOM の監視、Long Tasks API、購読件数と解除時間の集計、診断ファイルの保存を削除した。
UI の試験用表示と開発者向けの注意事項も削除した。
旧版の高速化設定を維持し、計測設定 `diagnosticsOrigins` は更新時に削除する。

自動テストとベンチマークは開発用として残し、配布 ZIP には含めない。
状態確認の通信と、ポップアップを開いている間の表示更新は引き続き使用する。

## 介入経路

トレースの購読解除関数は、公開配布ファイル `main.vendors.ed520e7e.js` の先頭行、列 127725 に記録されていた。
2026-11-13 に取得したファイルでは、対象はコンテキストを作るモジュール `900823` と、購読するフックのモジュール `62229` だった。
拡張機能は `rspackChunk_1js_m365_copilot_app` への登録時に両ファクトリーを同期的に照合し、一致した場合だけ差し替える。

| 対象 | SHA-256 |
|---|---|
| 配布ファイル全体 | `9285892ca0d492804e3d6083d7344889cdeb1278b9fb5c202b7a09d4aa3eb792` |
| `900823` の関数ソース | `778cbf87641dc6c5633db703eb58c01b6285186eec5b4e7a8ac4f01558afbdad` |
| `62229` の関数ソース | `5ecd5be924add02b83ed32d103ed1c742a444f9471933777c21c01976ed7abca` |

取得元：<https://res.public.onecdn.static.microsoft/midgard/versionless-v2/main.vendors.ed520e7e.js>

拡張機能自身は外部コードを取得せず、文字列からコードを生成しない。
最適化する範囲は、この 2 モジュールが生成するコンテキスト全体である。
React 全体や配列のプロトタイプは変更しない。
不一致では元のコードを通し、最適化した処理の例外では次回読み込み時の適用を無効にする。
変更済みのストアを戻すには再読み込みが必要になる。

## 購読管理

登録と解除に双方向リストを使い、解除関数から対象ノードを直接参照する。
通知中はノードの配列を作り、登録と解除を進行中の通知配列にも反映する。
元の `Array.forEach` の動作を保つため、通知中の解除は O(1) にはならない。
通知外の大量の解除を軽くする一方、通知時には O(N) の一時配列が増える。
この最適化の仕組みは 0.1.0 と同じで、計測用の処理だけを取り除いた。

## 開発と検証

```powershell
npm ci
npm run reference
npm test
npm run check
npm run package
```

`npm run reference` は比較試験用の配布ファイルを `research/vendors.js` に保存する。
既知の SHA-256 と一致しない場合は保存しない。
参考ファイルがない場合、そのファイルに依存する比較テストはスキップする。
比較試験は React のライフサイクルを模したハーネスを使い、実アプリ全体を再現してはいない。

ブラウザの結合テストは次の手順で実行する。
HTTPS の応答をローカルの検証用ページに差し替え、実アカウントで送信しない。

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.cache/browsers'
npx playwright-core install chromium --no-shell
npm run test:browser
```

`npm run benchmark` の計測は開発環境だけで実行し、実アプリの送信時間とは区別する。
利用者から実際の Copilot で改善したとの報告を受けているが、会社の Vivaldi と別実装への適用は未検証である。
拡張機能の実行に npm や開発用ライブラリは必要ない。

0.2.0 の最終確認では、参考ファイルを使った比較を含む単体テスト 21 件と、Chromium 158.0.8127.18 の隔離プロファイルによる結合テスト 9 項目が通過した。
計測を含まない状態通信、簡素化した UI、適用、コード不一致時の非適用、無効化と再読み込みを確認した。
