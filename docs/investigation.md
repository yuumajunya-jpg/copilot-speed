# Microsoft Copilot の送信遅延の調査

## 発生している問題

- 同じチャットで会話を重ねるほど、画面操作の応答が遅くなる。
- 数式を含む回答が増えると、特に悪化する傾向がある。
- 入力後に Enter または送信ボタンを押しても、入力欄に文章が残り、送信した発言が表示されるまで待たされる。

会社の Vivaldi・Microsoft 365 Copilot Chat で報告された症状であり、個人用 Copilot・Chrome でも発生している。

## 確認できた原因

個人用 Copilot・Chrome の送信ボタン操作を記録したトレースでは、メインスレッドの JavaScript 処理が約 10.3 秒継続していた。
CPU サンプル時間の約 89% は、React が画面部品を破棄する際の「購読解除」の関数に集中していた。

購読とは、共有状態が変わったときに画面部品へ通知するための関数を登録することである。
部品を破棄すると、その通知先の登録を解除する。
該当する配布コードでは、通知先を配列で管理し、解除時に `indexOf` で対象を探し、`splice` で削除して後続要素を詰めている。
この解除処理が、記録された送信遅延の主なボトルネックである。

| 記録された処理 | 時間 |
|---|---:|
| 送信クリックのイベント処理全体 | 約 10.33 秒 |
| 購読解除関数の推定自己時間 | 約 9.20 秒 |
| レイアウト計算 | 約 0.02 秒 |

購読解除の時間は CPU サンプリングによる推定値である。
この記録では、数式のレイアウト・描画が遅延の主因であることを示す結果にはなっていない。
解析対象は `Trace-20261113T210958.json.gz`。
元トレースはローカルの `research/traces/` に保管し、Git の管理対象から除外する。

## 未確定の点

送信時に部品の破棄が重くなる理由、購読数・解除回数、数式の増加との因果関係は未確定である。
Enter での送信および会社の環境でも同じ処理がボトルネックになるかは、このトレースでは確認していない。
